# gk 底座评估集多轮抖动分析（内部工作文档）

> **一句话定位**：对 gk 域底座金标准评估集（`src/main/resources/eval/golden-queries.json`，46 例）连跑六轮出现的「时过时不过」现象做逐例归因——结论是**引擎能力没有缺口，抖动来自 LLM 残余非确定性 × 用例良性歧义面的乘积**，可在金标准与 glossary 层面收敛。本文只分析不修复，修复动作待定优先级后另行执行。
>
> **背景**：2026-07-15，gk 分支。评估集已换为国库域 46 例（40 正向 + 6 失败关闭反例），40 条参考 SQL 均逐条对 `reportbigk` 真实数据执行验证通过；此前 C3（库名实体截断）与 C10（占位行口径矛盾）两例已修复（glossary 增「国库名称」词条 + few-shot 全称锚点 + 问法钉死）。本文分析的是修复后六轮实测的残余抖动。

---

## 一、六轮实测结果

| 轮次 | 失败用例 | 通过 |
|---|---|---|
| 第一轮 | C18、C30 | 44/46 |
| 第二轮 | —（全过） | 46/46 |
| 第三轮 | C11、C34、C38 | 43/46 |
| 第四轮 | C34 | 45/46 |
| 第五轮 | C19 | 45/46 |
| 第六轮 | C30、C34 | 44/46 |

**失败频次汇总**：C34 三次 > C30 两次 > C11 / C18 / C19 / C38 各一次。

## 二、总体解读

三个关键观察：

1. **没有任何用例连续失败**——每个抖动用例都有通过轮次（C34 也有三轮通过），单例单轮通过率约 93%~100%。这是「输出方差」的形态，不是「能力缺口」的形态（能力缺口的形态是同一用例每轮都挂）。
2. **temperature 已经是 0**（`application.yml` `llm.temperature: 0`，`OpenAiCompatibleLlmClient` 实际传给 API）。抖动不来自采样温度，而是两个残余源：
   - LLM 服务端在 temperature=0 下依然存在的非确定性（MoE 路由、批处理数值差异等供应商侧因素）；
   - `max-fix-rounds: 2` 自我修正路径的**分叉放大**——第一稿差一点的轮次会走上完全不同的修正轨迹，终稿形态随之分化。
3. **评估等价判定是刻意严格的**（`EvalService.runOnce`）：结果值多重集相等 + 列数相等 + 参考 SQL 含 order by 时保序。任何「业务上同样正确」的输出变体——多带一列、月份标签写法不同、剔不剔占位行——都判不等价。**严格性本身有价值（防宽松放水），代价是歧义面大的用例把 LLM 的输出方差如实暴露出来。**

因此抖动集中度与用例的「良性歧义面」大小严格正相关：歧义面越多（C34 双重歧义、失败三次），抖得越频繁。归因分三类：

| 类别 | 根因 | 涉及用例 |
|---|---|---|
| **A** | 占位行口径自相矛盾残留（glossary 建议剔除 `NNNNNNNNNN`，参考 SQL 却包含它——C10 修了个案，同类未清剿） | C34、C30 |
| **B** | 等价表示歧义（同一语义存在多种合法 SQL 表示，金标准未钉死取哪种） | C38、C19、C11 |
| **C** | 实体解析路径歧义（同一实体名在两条查询路径下解析结果不同） | C18 |

## 三、逐例分析（按失败次数从高到低）

### C34（失败 3 次）——占位行 + UNION 去重，双重歧义

> 问法：「把基础信息表的国库简称和日记账里出现过的所属县名称合并成一份去重名单，按名称排序」
> 参考：`select treasury_short_name as name from treasury_basic_info union select county_treasury_name from treasury_balance_journal order by name`（87 行）

失败最频繁，因为它同时踩着两个歧义：

1. **占位行歧义（A 类）**：日记账所属县名称的取值里含市库本级的占位行 `'NNNNNNNNNN'`，参考结果**包含**它；而 glossary「国库隶属」词条教 LLM「按县分组/筛选时注意把该占位行单独处理或剔除」——LLM 哪一轮听了 glossary 的话，87 行就变 86 行，判负。
2. **UNION vs UNION ALL 歧义**：两份名单有 10 个全称重叠（区县支库名同时出现在基础表简称与日记账所属县里）。「合并成去重名单」指向 UNION（去重，87 行），但 LLM 若先各自 distinct 再 UNION ALL、或直接 UNION ALL，结果 93 行，判负。

双重歧义叠加 → 单轮踩雷概率最高，6 轮 3 挂与此吻合。

### C30（失败 2 次）——分县排名的 partition 是否含占位县组

> 问法：「每个所属县中2026年6月30日余额排名前2的国库，列出所属县、国库简称、余额及组内排名，按所属县升序、余额降序排列」
> 参考：window `row_number() over (partition by county_treasury_name ...)`，rn≤2，**含**占位县组（市库在 `'NNNNNNNNNN'` 组里独占第 1），共 20 行 4 列

纯 A 类：参考的 partition 包含占位县组，glossary 却建议剔除——LLM 剔掉该组则 20 行变 18 行，判负。另有次级歧义（「及组内排名」是否输出 rn 列——少列则列数校验挂），但主嫌疑是占位行：与 C34 同源，正是 C10 修复时**只对齐了个案、没清剿同类**留下的尾巴。

### C11（失败 1 次）——「全辖」诱发形态分叉

> 问法：「2026年6月全辖借方发生额合计」
> 参考：`select sum(debit_amount) ... between '2026-06-01' and '2026-06-30'`（1 行 1 列）

B 类。「全辖」一词在 glossary 里对应「本库加全部下级」的机构树语义，可能诱发 LLM 按库分组、或 join 基础表做辖内下钻——单值变多行/多列即判负。此外「按月」语义也可能让 LLM 改用生成列 `stat_month='202606'` 过滤（结果值相同、不影响判定），真正致命的是**分组形态**分叉。

### C18（失败 1 次）——「昆山市」的双路径解析

> 问法：「昆山市2026年6月的一般公共预算收入本期金额」
> 参考：`... treasury_income_detail where ... and treasury_short_name='昆山市'`（收入表直接短名等值）

C 类。「昆山市」有两条解析路径：①收入表 `treasury_short_name` 直接等值（该表存**行政区短名**，命中）；②经 `treasury_basic_info` 找库代码再过滤（该表存**全称**「国家金库昆山市支库」，用「昆山市」等值查空 → 0 行判负）。glossary「国库名称」词条已写明两表取值风格差异与「跨表用 treasury_code 关联」，但**选哪条路仍由 LLM 临场决定**——走错路的那一轮即失败。这是 C3 修复（journal 表全称截断）的镜像问题：同一个「两表同名字段不同取值风格」的数据陷阱，在收入表方向的残余。

### C19（失败 1 次）——分组键与输出列数

> 问法：「2026年6月各国库的税收收入本期金额，从高到低取前5」
> 参考：`group by treasury_short_name`（2 列：简称、金额）

B 类。「各国库」的分组键选择有变体：group by 简称（2 列）、group by 库代码+简称（3 列）、group by 代码后 join 出简称——值可能全对，**列数**校验挂。问法没有像 C1/C6 那样显式给「列出简称和金额」的列清单，把列形态留给了 LLM。

### C38（失败 1 次）——月份标签的两种合法表示

> 问法：「按月份统计2026年的借方发生额合计，列出月份和金额，按月份排序」
> 参考：`date_format(stat_date,'%Y-%m')` → 月份标签形如 `'2026-01'`

B 类中最典型的「两种合法表示打架」：日记账 schema 里有生成列 `stat_month`（char(6)，注释还写着「方便按月汇总」）——LLM 用它分组**完全正当且更高效**，但标签是 `'202601'`，与参考的 `'2026-01'` 值签名不等，判负。这一例严格说是**金标准自己没钉死格式**，反而是 LLM 读注释读得越认真越容易「犯错」。

## 四、后续方向（按性价比排序，本文不执行）

1. **拿实证坐实归因**：评估响应的每个失败 case 都带 `generatedSql`——下次失败时把这几条存下来，上面的嫌疑逐一坐实或排除（尤其 C34 到底是占位行还是 UNION ALL）。必要时用 `runs` 参数跑 pass@N 看每例通过率分布。
2. **清剿 A 类矛盾（治本，收益最大）**：占位行规则二选一后全局对齐——要么 glossary 定「默认剔除 `NNNNNNNNNN`，除非明确要求含市库本级」、金标准 C30/C34 参考随之剔除；要么反向。定死其一，最大抖源即消失（预计消除 6 轮 5 次失败中的 5 次里的大头）。
3. **B/C 类钉死金标准问法**（微调，不改语义资产）：
   - C38：问法注明月份格式（如「月份格式形如 2026-01」），或参考改用 `stat_month` 表示；
   - C19：显式「列出国库简称和金额两列」；
   - C11：显式「只要一个合计数」；
   - C18：显式「按收入表简称『昆山市』统计」，或将该例改为考察 code 关联路径。
4. **评估报告口径升级**：`EvalService` 已支持 pass@N——对外汇报准确率时用 pass@3（或标注单轮方差）比单轮数字更诚实，也能把「能力缺口」与「输出方差」区分开呈现。

**一句话收束**：46 例金标准里 40 例六轮全稳，抖动的 6 例全部指向三个可收敛的歧义源——占位行口径自相矛盾（最大头）、等价表示未钉死、实体解析双路径；修复应优先清剿 A 类，再微调 B/C 类问法，引擎侧无需改动。
